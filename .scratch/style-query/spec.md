# 样式守卫：查询收成一个 module，三处瞎测的断言变红

**Status:** ready-for-agent

**来源:** `/improve-codebase-architecture` 的候选 ⑩，经 `/grilling` 四轮定型。报告把它标成 Speculative，核对后发现三处 **live** 缺陷，据此升格。相关决定：本轮新立的一条 ADR（样式断言查源码文本，不查编译产物也不查浏览器 computed 值）。

## Problem Statement

样式守卫那个测试文件有 1669 行、95 个测试、735 条断言，是全仓最大的测试文件之一。它守的东西全是管理员看得见的：浮层叠放次序、撤回消息的删除线、气泡圆角、头像尺寸、主胶囊毛玻璃、鼠标指针不被覆盖。

它靠**手写的文本切片器**读 SCSS：6 个助手名背后只有 3 种切片行为，另有第 4 种风格是手写惰性正则提属性值。这些切片器有三处已经在瞎测：

**一条断言测的是空串，无条件通过。** 「撤回气泡里不该有 `top: 50%`」那条——它要的选择器在 SCSS 里写成逗号选择器列表的第一项，而默认那个切片器只认「选择器 后跟空格花括号」，永远匹配不上，返回空串。同一个测试往上三行用的正是会校验逗号前导的那个careful 切片器：对的访问器就在旁边，而错的那个是默认，374 次对 72 次。

**一对断言里有一条守不住它看起来在守的东西。** 通知菜单那两条，前一条的针是后一条的针的子串，而那个选择器在 SCSS 里根本没有裸规则、只作为逗号列表成员出现。删掉其中一处用法，前一条照样通过。

**全仓最大的样式文件对规则访问器完全不可见。** 浮层与交互样式那个文件 1503 行、184 个块，占全部样式源（5398 行）的 28%，它被读进来但没拼进那份供切片器查询的大字符串。所以任何针对它的规则查询会静默返回空串，而它现在只被「整个 1503 行里出现这串字即通过」这种最弱的形态查过。

除此之外还有两处结构性隐患：17 条负向断言的主体是那个默认切片器，只要选择器改名就静默变成永真（全文只有 2 处证明过切出来的内容非空）；以及切片器不剥注释，而同仓的排版守卫已经证明必须剥。

## Solution

把 9 个手写助手收成**一个共享的样式查询 module**，两个样式测试文件共用。

它有五个方法，各自小而明确：取规则的本级声明、问规则是否存在、取块的全部内容、取两个字面量之间、取某条声明的值。找不到就报错，不再返回空串；同一个选择器有多处定义时也报错，要求调用点把来源收窄。剥注释是它的内置行为。

那份供查询的大字符串补上漏掉的两个样式文件，覆盖率从 71% 到 100%。

**断言的参数一条都不改**——还是「这条规则里应该有 `padding: 8px`」。只有主体换访问器。三处瞎测的断言在迁移后会变红或报错，那正是这一票的验收。

管理员看不到任何变化：样式一行都不改，生产代码零改动。

## Implementation Decisions

### 范围为什么与复查报告不同

报告说的两个数字都准：「684 条断言」正好是正向 `toContain` 的条数，「4 个解析器」也比「6 个助手」更贴近事实——6 个名字背后只有 3 种切片行为，加上手写正则提属性值恰好是第 4 种。

报告漏掉的是**三处 live 缺陷**：一条测空串的死断言、一对子串型冗余断言、以及全仓最大的样式文件对规则访问器不可见。凭这三条它不再是 Speculative。

报告没提但同样要紧的是两处结构性隐患：17 条负向断言的主体是那个不校验的默认切片器；切片器不剥注释。这两条目前是 latent——注释里出现过的选择器字面量只有两个，都没被正向整文件断言用到——但它们正是让那条死断言藏了这么久的机制。

### 为什么不换成真解析

Sass 编译器已经在开发依赖里，所以「为什么不用它」一定会被再问。答案不显然，要写在 ADR 里。

这些断言守的是「**源码里写了这条声明**」。项目自己的样式规则也是这么表述的——比如「不得新增任何 `cursor` 声明」、「字号必须来自集中定义的标度令牌」。Sass 求值会把它们要守的东西改写掉，而且改写多少是个未知数。

「编译更准」这个直觉在这里是错的：全部断言里只有 1 条依赖嵌套语法存活，所以编译能多解析的东西几乎没有；而编译会让一整类源码级规则失去检查对象。

浏览器读 computed 值是另一层验证，不是这一层的替代品——那一层跑不了 735 条断言，也看不到「源码里写没写」。

### 样式查询 module 的形态

五个方法，都接受可选来源，都剥注释：

- **取规则的本级声明**——默认形态。255 条可配对断言里 246 条的声明在本级，所以「本级」是默认而不是选项。找不到就报错。
- **问规则是否存在**（返回布尔）——有三处判据是「这条规则不该存在」，它们现在靠切片器返回空串来表达。存在性与内容是两个不同的问题，混进一个返回值会让调用点重新长出 `if (body)`，等于把刚消灭的空过形态换个样子留下。
- **取块的全部内容**——给 `@keyframes` 与 `@media`，它们的 body 本来就只有嵌套块。
- **取两个字面量之间**——现有用法 3 处，直接搬。
- **取某条声明的值**——替掉 7 处手写的惰性正则。那些正则今天读到的值是对的，但失效形态是「目标规则没有这条声明时静默读到后面某条无关规则的值」，而它们服务的是浮层叠放次序断言。

一个方法带选项对象的方案被否掉：446 个调用点都要读一遍选项含义，而五个小方法各自一眼能读懂在问什么。

module 落在既有的共享测试脚手架目录，是纯测试设施，不进生产代码。

### 查询来源与歧义

把漏掉的两个样式文件（浮层与交互样式、盒模型基线）补进那份拼接串，覆盖率从 71% 到 100%。

**规则访问器在同一个选择器有多处定义时报错**，要求调用点收窄来源。补文件后，被查过的 236 个选择器里有 25 个存在多处定义，其中 6 个是**同一文件内**重复——所以「指定文件」本身不够，必须能收窄到父规则的 body。

**消歧靠收窄来源，不引入序号参数。** 序号会让断言依赖规则在文件里的顺序，那正是这一票在消灭的东西。收窄来源不是新发明：现在已经有 20 多处写成「在浮层样式这个文件里查」，还有一处写成「在已切出的父规则 body 里查子选择器」。

那条唯一性检查不只是洁癖——它是这次迁移的安全网。把最大那个文件拼进来会让某些选择器的首命中变成另一处，凡是因此变红的地方都是原来在瞎测的地方。

### 消歧发现样式该改时本轮不改样式

有的歧义会指向样式表本身（比如浮层样式里有一个选择器写了两个块，一个只放自定义属性、一个是真规则）。本轮**不合并它们**。

理由是安全网：迁移 446 个调用点时，「样式一行没改」是唯一能让人分清「我改坏了断言」和「原来这里在瞎测」的东西。合并两个同选择器块会改变声明顺序，进而可能改层叠结果，那就得上浏览器验证，整票的性质与验收强度都变了。发现写进票的 Comments，值得的话另开票。

### 断言怎么迁

**参数一条都不改**，只换主体。这是这一票风险可控的全部原因。

- 9 条依赖嵌套内容的分三拨：`@keyframes` 与 `@media` 改用块访问器；真正「规则却要子规则内容」的两三条改成嵌套查询（先取父规则的本级 body，再在里面查子选择器，现有写法里已有一处）；唯一那条依赖嵌套语法 `&` 的正则**原样保留**——它测的是 SCSS 源码里的嵌套写法本身，换成任何访问器都会把它要测的东西抹掉。
- 17 条负向断言里，凡是整个测试对同一个 body **只有**负向断言、连一条正向都没有的，补一条最小的正向断言。那条死断言正是这种形态，所以没有任何东西能揭穿它切了个空串。不逐条都配——那会新增几十条低价值断言。
- 整文件断言按形态分开处理：断言「某个选择器存在」的收紧成「问规则是否存在」（那对子串型冗余断言就是这一类，收紧后前一条才能独立失败）；整文件 `toMatch` **保留**——它们测跨规则的模式或全文禁令（比如「全文不得出现 `cursor:`」），主体本来就该是整份源码，收窄反而会漏。
- 5 处临时把源码再拼一次的写法自动消失——它们存在的唯一原因就是最大那个文件没进主拼接串。

### 组件源码断言与样式查询分开

有 17 条断言读的是 7 个组件的单文件组件源码，断言类名与标记存在。它们**不动**，但本轮要明确它们不属于样式查询 module 的职责：它们守的是「组件带没带这个类名」，那是组件契约不是样式契约，混进来会让 module 多吃一种输入。

真要处理，它们更该退役给挂载式断言（仓库里已有大量先例），但那是另一票。

### 排版守卫并进来的边界

排版守卫那个测试文件有 3 个助手，其中**剥注释这件事它做对了**而样式守卫没做。新 module 必须有剥注释，所以它跟着改用新 module——不并的话仓库里会同时存在两份剥注释实现，而这一票的主题恰好是消灭重复的样式查询助手。

但「取第 N 条规则的选择器清单」**不进 module**：那是排版守卫特有的遍历方式（它要逐条核对根容器与各浮层的基准字号声明），不是通用查询，进了会把接口撑宽第六项。

### 没有生产代码改动

样式一行不改，生产代码零改动。改的全部是测试与测试脚手架。

## Testing Decisions

### 什么算好测试

这一票测的对象**就是测试自己**，所以「只测外部行为」这条要落在两个层面。

样式守卫的外部行为不变：给定一份 SCSS 源码，某条规则里应该有某条声明。断言的参数一条不改就是这个意思——外部行为的表述完全没动，动的只是读取它的方式。

样式查询 module 自己的外部行为是「给一个选择器和一份来源，返回什么、什么时候报错」。它需要自己的断言：找不到报错、多处定义报错、只取本级、剥注释后才匹配。

### 接缝

一个，新建的：**样式查询 module 的五个方法**。它落在这条缝的最高点——两个样式测试文件的全部查询都过它。

不新造第二个。组件源码那 17 条断言继续直接读文本，它们不经过这个 module，也不该经过。

### 失效实测要做两种

第一种照常：改坏 SCSS，对应断言变红。这一种覆盖的是「守卫还在守」。

**第二种是这一票的验收核心**：证明新访问器抓得到旧访问器抓不到的东西。

- 那条测空串的死断言，迁移前对空串通过、迁移后必须**报错**
- 那对子串型断言收紧后，删掉逗号列表里的那处用法，前一条必须**独立变红**
- 浮层样式里那个写了两个块的选择器交给规则访问器，必须触发**唯一性报错**，而不是静默取第一处
- 给某条被查询的规则加一句带花括号的注释，断言不得因此量错对象

没有第二种，这一票就只是换了套写法。

### 验收强度

`yarn typecheck` + `yarn test` + `yarn build`。**不需要浏览器验证**——一行样式都没改，生产代码零改动。

### Prior art

剥注释的正确实现在排版守卫那个文件里已有一份（它的注释写明了原因：盒模型基线的注释里就带着花括号）。「找不到就抛错」的做法同一个文件里也有一份。校验逗号前导的切片器在样式守卫里已经存在，只是用得少——本轮是把它变成默认。共享测试脚手架目录本身是上一系列建立的，直接沿用。

## Out of Scope

- 换成 Sass 真解析。理由见 ADR：这些断言守的是源码里写了什么，编译会把它们要守的东西改写掉，而只有 1 条断言需要嵌套语法存活。
- 改成浏览器读 computed 值。那是另一层验证，不是这一层的替代品。
- 合并样式表里那些同选择器的重复块。会改变声明顺序进而可能改层叠结果，失掉「样式一行没改」这张安全网。
- 改动任何一条断言的**参数**。外部行为不动。
- 把读组件源码的 17 条断言退役给挂载式断言。是另一票。
- 把排版守卫特有的「取第 N 条规则的选择器清单」放进 module。不是通用查询。
- 给样式查询 module 加序号参数。会让断言依赖规则在文件里的顺序。
- 收窄整文件 `toMatch` 那些断言。它们测跨规则模式与全文禁令，主体本来就该是整份源码。
- 领域术语。样式查询助手是纯测试机制，词汇表要保持不含实现细节。

## Further Notes

### 为什么这一票比看上去小

446 个调用点听起来像宗大工程，但其中绝大多数是机械替换，因为**断言的参数不变**。真正需要判断的只有四类：9 条依赖嵌套内容的、25 个歧义选择器的收窄、17 条负向断言里要补正向的那几条、以及要收紧的那几条整文件断言。四类加起来五十条上下。

### 迁移中间态会不会全绿

不会，而且这是有意的。补上最大那个文件、打开唯一性检查之后，凡是原来在瞎测的地方都会变红或报错。那些红是迁移的产出而不是事故——每一处都要判断「原来它想测什么」，然后收窄来源或改用别的方法。

### 三处 live 缺陷的共同形状

它们都是「访问器取不到东西时静默返回空/取到别人的东西」，而断言的形态又刚好让这种静默通过。这跟上一系列消灭的源码位置比较断言是同一类：证明得了源码里有某段文字，证明不了那段文字是断言想量的那一处。

### 速度不是理由

样式守卫那 95 个测试跑 14ms，整个文件加载 235ms。这一票不为性能做任何事。
