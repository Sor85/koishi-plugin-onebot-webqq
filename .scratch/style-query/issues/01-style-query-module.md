# 01 — 样式查询 module 立起来

**What to build:** 一个能被任何样式测试文件 import 的**样式查询 module**，读 SCSS 源码回答五种问题，而且切不出东西时报错而不是返回空串。

这是后面两张票的前置，走的是 expand–contract 的 expand：本票**不迁移任何调用点**，旧助手一行不动，两套并存，全绿。把 module 的语义先钉住，再让 446 个调用点依赖它。

管理员看不到任何变化。样式一行不改，生产代码零改动。

**Blocked by:** 无 — 可以立即开工。

**Status:** resolved

**参考:** `.scratch/style-query/spec.md` 的「样式查询 module 的形态」、「查询来源与歧义」、「什么算好测试」；剥注释与「找不到就抛错」的现成实现在排版守卫那个测试文件里；共享测试脚手架目录是上一系列建立的。

- [x] module 住在既有的共享测试脚手架目录，是纯测试设施，不进生产代码
- [x] 五个方法：取规则的**本级声明**、问规则是否存在（布尔）、取块的全部内容、取两个字面量之间、取某条声明的值
- [x] 「本级声明」是默认而不是选项——255 条可配对断言里 246 条要的就是这个
- [x] 五个方法都接受可选来源，来源可以是某个文件的内容，也可以是上一次切出的父规则 body
- [x] 剥注释是内置行为，不是调用点各自记得做
- [x] 规则访问器找不到目标时**报错**，错误信息带上选择器；不返回空串
- [x] 取某条声明的值时，目标规则没有这条声明也**报错**，不静默读到后面某条规则的值
- [x] 规则访问器在同一个选择器有多处定义时**报错**，提示调用点收窄来源
- [x] **不加序号参数**（「要第几处定义」）——序号会让断言依赖规则在文件里的顺序，正是本系列在消灭的东西
- [x] 默认来源覆盖**全部**样式文件，包括现在漏掉的浮层与交互样式（全仓最大，1503 行）与盒模型基线
- [x] module 自己的断言：找不到报错、同选择器多处定义报错、只取本级不含子规则、逗号列表成员算规则存在、带花括号的注释不影响切片、块访问器能取到 `@keyframes` 的全部内容、声明值访问器在缺声明时报错
- [x] **旧助手一行不动**，本票不迁移任何调用点；两套并存
- [x] 全量测试通过，不出现任何新的红

## Comments

module 住在 `tests/helpers/style-query.ts`，五个导出：`ruleDeclarations`、`hasRule`、`ruleBlock`、`sourceBetween`、`declarationValue`。另外导出 `styleSources`（按 `@use` 顺序排列的 14 个样式源）、`allStyles`（默认来源）与 `withoutComments`（排版守卫复用同一份剥注释）。断言在 `tests/style-query.test.ts`，14 条。

默认来源覆盖全部 14 个样式文件（5398 行），不只是票里点名的浮层样式与盒模型基线——排版基线也一起补上了，否则覆盖率停在 99%。

实现上有两处不显然的地方，都写了注释：

- **前导边界要算上 `;`**，不能只按花括号找。`.foo { color: red; &:hover { … } }` 里嵌套规则的前导紧跟在声明后面，只按花括号找会把 `color: red; &:hover` 整段当成前导，嵌套规则永远查不到。
- **拆前导选择器要按顶层逗号**，括号内的逗号不算。浮层样式里有 `body[…] :is(.webqq-dialog-content, .webqq-context-menu-content, …)`，按裸逗号拆会让 `.webqq-dialog-content` 凭空多出一处「定义」。

### 代码评审之后的两处补强

- 「默认来源覆盖全部样式文件」原来那条断言是恒真的：它遍历 `Object.values(styleSources)` 断言 `allStyles` 包含每一项，而 `allStyles` 就是这些值 `join` 出来的。改成把 module 声明的清单（`styleSourceFiles`）与磁盘上 `client/**/*.scss` 的实况比对。失效实测：临时新增一个未登记的 `.scss`，守卫变红。这条恒真断言与票里第三条 live 缺陷同形态，是同一类错误在守卫自己身上又犯了一次。
- 全树遍历原来有两份（module 的手写清单 + 排版守卫的递归读取）。收成 module 的 `collectClientSources`，排版守卫改为复用，新增样式文件时不会只想到一处。
- 剥注释加了按来源字符串的记忆化。唯一性检查让每次查询都要扫一遍来源里的全部花括号，样式守卫从迁移前的 14ms 涨到 318ms；记忆化后回到 188ms，剩下的开销是唯一性检查本身，不再优化（已写进 ADR 0011 的后果）。
