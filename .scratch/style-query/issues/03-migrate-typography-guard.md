# 03 — 排版守卫迁到样式查询 module

**What to build:** 剥注释这件事全仓只有一份实现。

排版守卫是同一件事的 careful 版本——它剥注释、找不到就抛错，而样式守卫两样都没做。样式查询 module 把这两条语义收了进去，所以排版守卫也要改用它，否则仓库里会同时存在两份剥注释实现，而消灭重复的样式查询助手正是这一系列的主题。

本票很小：那个测试文件 150 行、14 条断言、3 个助手，只有一个助手该进 module。

**Blocked by:** 01 — 样式查询 module 立起来。（不需要 02：那是另一个测试文件，两票并行。）

**Status:** resolved

**参考:** `.scratch/style-query/spec.md` 的「排版守卫并进来的边界」；排版验收要求实测 computed 值这一条是另一层验证，不受本票影响。

- [x] 剥注释改用样式查询 module 那一份，本地那份删掉
- [x] 「取第 N 条规则的选择器清单」**留在原文件，不进 module**——那是排版守卫特有的遍历方式（逐条核对根容器与各浮层的基准字号声明），进了会把 module 的接口撑宽第六项
- [x] 「找不到就抛错」的语义不退化：原来那个按第 N 次出现取位置的助手会抛错并带上说明，迁移后仍然要在找不到时明确失败
- [x] 那 14 条断言全部仍然通过，一条都不改参数
- [x] 失效实测：改坏排版令牌与基准字号声明，对应断言变红；给被查询的规则加一句带花括号的注释，断言不受影响
- [x] 样式一行不改，生产代码零改动
- [x] `yarn typecheck`、`yarn test` 与 `yarn build` 通过

## Comments

`withoutComments` 改成从 module 导入，本地那份删掉。`selectorList` 与它依赖的 `nthIndexOf` 留在原文件（`nthIndexOf` 找不到第 N 个花括号时仍然抛错，语义没退化）。

顺手把四个具名样式源换成 `styleSources` 的对应键，本地的 `source(name)` 查找函数删掉；`collectStyleSources` 保留并改名为 `sweepSources`，它服务的是「全树扫描字号野值」，要连 `.vue` 一起读，跟样式查询那份清单不是一回事。

草稿文字那两条断言原来用 `chatStyle.slice(indexOf(sel), indexOf('}'))` 取规则体——遇到带嵌套的规则会截在第一个内层花括号上。改用 `ruleDeclarations`，参数没动。

失效实测：把 `--onebot-webqq-font-md` 从 13px 改成 14px，「字号标度是集中定义的七档令牌」变红；给被查询的规则插一句带花括号的注释，断言不受影响。
