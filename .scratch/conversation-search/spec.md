# 会话内查找：编排收成 module，行为交给断言

**Status:** ready-for-agent

**来源:** `/improve-codebase-architecture` 的候选 ③，经 `/grilling` 四轮定型。相关决定：ADR 0006（客户端侧超时）、ADR 0001（模块边界与依赖方向）、ADR 0003（`client` 侧 import `src` 模块的判据）、ADR 0004（对照：什么时候才该做成组件）。

## Problem Statement

管理员在一级工作区顶部用**会话内查找**定位历史消息。这条路径上有几类问题，现在只能靠碰运气复现：

- 连着改**查找条件**时，慢的那次请求后返回，可能把新条件的结果盖掉。
- 搜索途中切会话，上一个会话的**命中**可能落到状态里。
- 控制台连接不通时，服务端自己的预算不会被触发，界面停在「搜索中...」。
- 往更早历史翻页时**续查游标**算错，会重复或漏掉消息。

维护者这一侧的问题更具体：同一个能力被一条测试线切成了两半。后端的查找有 8 条断言守着分页、游标推进、去重与双层超时预算；前端这半——10 个 ref、竞态丢弃、12 秒超时、游标累加、命中落地，约 120 行——一条行为断言都没有，只有 10 条读源码文本的断言（`searchWebQQMessages({`、`if (localMatches.length)` 这类）。改这段代码时，测试只能告诉你「那行字还在」，不能告诉你「竞态还对」。

## Solution

把查找编排从观察窗 SFC 搬进 `client/webqq/stores/webqq-message-search.ts`，形状与已有的 11 个 store 一致：注入 ref 与函数，返回状态与动作。查询、缓存读取、发送者元数据记录、滚动到命中、恢复触发按钮焦点全部作为注入函数，测试注入假实现即可在无 DOM 环境里把时序场景精确造出来（先返回慢的、再返回快的；搜索途中换会话；超时注入 5 毫秒）。

查找页组件本来就是纯 props/emits，本轮同时给它立挂载式断言——防抖、日历排布、Escape 分层、外部点击关闭这些行为目前一条守卫都没有。

管理员看到的界面与交互不变；两处不可见的行为修正方向都是少做无用功。

## Implementation Decisions

### 查找编排的形态

查找编排落成 `stores/` 下的一个 composable，不做成组件。判据是 ADR 0004 立下的那条：**行为长在 DOM 上才做组件**。输入区必须是组件，因为它的行为就是光标、输入法与粘贴；查找编排一行 DOM 都不碰，做成组件等于凭空造一个没有模板的组件，还要为了测试去挂载它。composable 能跑在默认的 node 环境，不需要按文件开无头 DOM。

命名沿用既有 store 的 `webqq-message-*` 序列，与后端同名模块对照。**会话内查找**是散文里的说法，代码标识符不必逐字对齐——把 RPC 名、后端模块、查找页组件与一整套类名一起改名是宽重构，与本轮无关。

### 注入什么，不注入什么

注入：当前会话、消息列表 ref（本地池与命中落地都要用）、查询函数、缓存读取函数、发送者元数据记录函数、滚动到命中的函数、恢复触发按钮焦点的函数、客户端超时毫秒数（可选）。

直接 import：合并消息、本地筛选、本地日期转日期范围、错误文案读取——都是纯函数，注入它们只会把接口撑宽而换不到任何可替换性。

**不给查询能力单独命名一个端口类型。** 接缝是 options 对象本身，11 个既有 store 都是这个形状。给一个单方法的能力套上命名 interface，调用方要多学一个名字，换来的是零；那是浅模块的定义。

滚动到命中的注入函数收一个命中键，键由模块自己算；`await nextTick()` 也留在模块里——命中并进消息列表后必须先渲染才能滚过去，这个先后顺序是编排的职责。

### 留在观察窗 SFC 的东西

触发按钮的 DOM 引用与 `visible`、以及恢复焦点时那 50 毫秒的等待（要等整条指针事件链结束，注释已说明原因）。是否渲染查找页的门禁（有没有当前会话）也留在 SFC。模块只暴露一个「把焦点还回去」的回调让 SFC 实现。

### 双层超时

服务端每页 4 秒、每次查找 8 秒；客户端另有一层 12 秒。两者守的不是同一件事，理由与替代方案见 ADR 0006。客户端这层的毫秒数作为模块可选参数（生产不传），计时器必须在 `finally` 里清掉。

### 本轮允许的两处行为改动

除下面两处，其余按逐字等价搬迁处理。两处方向相同：少做注定作废的功，管理员看不到变化。

1. **本地命中上屏前补齐守卫。** 现在读浏览器缓存是 `await`，读完直接把本地命中写上屏，没有竞态序号与会话校验（远端结果落地那条路径有）。补上之后，缓存读取期间切走会话就不再写状态。它现在不出事只是因为另外两处顺手清理掩掉了后果，不是因为守卫存在。
2. **守卫命中就整个返回，不再发查询请求。** 会话已经切走，这次查询的结果 100% 会在落地前被丢弃，而服务端那边会真的向 OneBot 翻最多 10 页历史。

### 删掉一条死接口

「已扫描条数」这条状态被逐页累加、绑到查找页的 prop 上，但查找页从头到尾没有读过它。删掉模块内的累加、观察窗的绑定与查找页的 prop 声明，对外状态从 9 条降到 8 条。后端契约与前端的响应归一化都保留——将来真要显示「已扫描 N 条」时数据还在，只是不再攒一个没人看的数。

### 有意保留的冗余

前端读浏览器缓存本地筛一遍，服务端也自己扫一份本地记录，两处池子不同。这不是重复代码：浏览器后端的持久化缓存只存在于前端，服务端拿不到；服务端能看到 Koishi 库与实时消息，前端拿不全。本轮保持不变，并用一条断言把「本地池包含还没落盘的内存消息」钉住——这是这份冗余存在的理由。

### 跨界 import

本地筛选函数从 `client` 侧 import `src/webqq/message-search`。这不是例外：`client` 里已有 5 处指向 `src/config/spec` 的同类 import。判据是 ADR 0003 立的那条——被 import 的 `src` 模块不得引入 `koishi` 运行时（前端 vite 的 external 只有 `vue` 与 `@koishijs/client`，多引入的东西会被静默打进产物）。该模块只有一行 `import type`，且其类型来源模块零 import，编译后运行时依赖为空，满足判据。

### 新增领域术语

`CONTEXT.md` 新开一节 `查找与筛选`，六条：**会话内查找**、**查找条件**、**命中**、**续查游标**，以及用来与之区分的**联系人筛选**、**成员筛选**。这个 UI 里原本有三个东西都叫「搜索」（侧边栏联系人、群成员、会话历史），只给其中一个立名字、把另两个列进 _Avoid_ 是无法执行的禁令。三者的区别是领域区别而非实现区别：**筛选**在已经列出的集合里就地过滤，**查找**会取回还不在手上的消息。

## Testing Decisions

### 什么算好测试

只测外部行为。对查找编排来说，外部行为是「给定注入的假实现与一串动作，模块返回的状态与它对注入函数的调用应当是什么」；对查找页来说，是「给定 props 与真实事件，渲染结果与 emits 应当是什么」。断言源码文本不算测试行为——它锁的是实现语句，改写等价代码会误报，改坏行为反而可能照过。

### 接缝

两个，都已存在，本轮不新造：

1. **查找编排的 options 对象**。与 `useWebQQNotices` 现有那条断言同款——直接实例化、注入假函数、调动作、读状态。跑在默认 node 环境。
2. **查找页的挂载面**。与输入区那四个测试文件同款——`@vue/test-utils` + happy-dom 按文件开环境。查找页已经是纯 props/emits 组件，不需要任何改造就能挂。

### 查找编排要测的行为（15 条）

空**查找条件**不发请求且重置状态；本地**命中**先上屏；远端返回后与本地命中合并去重；本地池包含还没落盘的内存消息；竞态（后发先回、先发后回 → 先发的被丢弃）；切会话时远端结果在途 → 丢弃；切会话时还在读缓存阶段 → 不写状态也不发请求；超时（注入 5 毫秒）→ 错误文案为「查找聊天记录超时」；超时计时器在查找结束后归零；本地有命中时远端失败不报错；本地无命中时远端失败报错；翻页带上**续查游标**、不重置、结果追加、游标与「已到底」更新；命中落地（并入消息列表 + 记发送者元数据 + `nextTick` 后调滚动函数并传对的键）；关闭时重置并调恢复焦点回调；打开时重置结果。

不测：游标不前进时的兜底（后端模块已有断言，前端重测等于抄一遍）、竞态序号本身（内部实现，由竞态那两条间接覆盖）。

### 查找页要测的行为（13 条）

防抖（250 毫秒内连续输入只发一次查找）；清空输入立刻发（不等防抖）；每次输入都同步发出查询串更新（防抖只压查找）；无**查找条件**时结果面板不存在；状态文案三态优先级（错误 > 搜索中 > 无匹配）；点命中发出选中事件；「加载更多结果」的显示条件与加载中禁用；日历选日期发出日期更新与查找并关闭浮层；Escape 三层收起顺序（月/年菜单 → 日期浮层 → 关闭查找）；外部 pointerdown 关闭、点内部不关；挂载后输入框自动聚焦且带 `preventScroll`；卸载后再点外面不再发出关闭；日历排布（42 格、周一起始、跨月与今天/选中的标记）。

日历排布那条只断言排布性质，不逐格比对。周一起始的偏移计算是这个组件里最容易写错又最难目视发现的一处。

### 时间怎么测

超时靠注入小值，不用假计时器——它有注入点，注入值把时间变成参数，比推进假计时器稳，不必操心微任务与计时器的交错顺序。防抖那 250 毫秒硬编码在查找页内部，没有注入点，也不值得为测试开一个 prop，用假计时器。计时器清理那条例外地用假计时器 + 计时器计数：测「超时会触发」和测「计时器被清掉」是两件事，后者本来就得看计时器。

### 无头 DOM 的能力边界

happy-dom 20.12.0 **没有 Popover API**（`showPopover` 是 `undefined`）。这不影响查找页挂载：项目的浮层提升工具本来就守了这个判断并静默返回，popover 是渐进增强。日历的开合、月/年菜单、选日期、Escape 分层全是普通 DOM，都可断言；测不到的只有「浮层被提升到 Top Layer」，那由保留的源码契约断言加真实浏览器覆盖。

### 保留与删除

删（10 条，全在观察窗源码断言里，锁的是查找编排的实现语句）：触发按钮聚焦语句、日期范围转换调用、查询 RPC 调用、本地筛选函数名、缓存读取调用、超时错误构造、本地命中判断、续查游标赋值、滚动到命中的调用、日期 `v-model` 绑定。接管者全部在编排的 15 条里。

删（4 条，在查找页源码断言里）：聚焦状态类、失焦处理器绑定、输入框聚焦语句、浮层提升调用。接管者在查找页的 13 条里。

改成挂载后的渲染断言（3 条）：查找框容器类、占位文案、日历网格类。

原文保留：观察窗上锁门禁与模板结构的 6 条、消息列表 `defineExpose` 契约的 2 条、RPC 名 1 条、查找页的 6 条契约守卫（`popover="manual"`、毛玻璃三元、命名空间 `not.toContain`、滚动条指令、`not.toContain('<Teleport')`、`not.toContain('message-search-backdrop')`）。日期浮层那个 data 属性也保留——它是跨文件契约，胶囊的外部点击判定在用它。

### Prior art

`tests/webqq-view.test.ts` 里 `useWebQQNotices` 那条断言是编排测试的范本（注入假函数、事件序列断言）。`tests/webqq-composer-*.test.ts` 四个文件与 `tests/helpers/webqq-composer.ts` 是挂载式断言的范本。`tests/message-search.test.ts` 是同一能力后端那半的断言，本轮不动它，前端的断言不要与它重叠。

## Out of Scope

- 改查找的用户可见行为、界面或交互。除上面点名的两处不可见修正外，按逐字等价搬迁处理。
- 把 RPC 名、后端模块名、查找页组件名或 `__message-search-*` 类名改成新术语。宽重构，与本轮无关。
- 给 `client → src` 这类跨界 import 立自动守卫。有价值，但它是**配置规格**那轮的尾巴（ADR 0003 自己承认这类问题「只能靠检查构建产物发现」），归属不在会话内查找。
- 后端查找模块的任何改动，包括它的两层预算默认值。
- 查找页的样式契约断言（毛玻璃、滚动条、Top Layer 提升）——属于样式契约那个候选。
- 把「已扫描条数」显示到界面上。本轮只是删掉它没人消费的那一半。

## Further Notes

### 验收清单

两张票各自的验收写在票里。跨两张票的共同要求：全量测试通过；删掉的每一条源码断言都能指名接管它的行为断言；逐条失效实测（故意改坏 → 对应断言变红 → 改回）。

### 真实浏览器

本轮不需要真实浏览器回归。查找路径上没有输入法、没有剪贴板、没有需要真实布局的几何计算——上一轮输入区之所以必须进浏览器，是因为那三样在无头 DOM 里测不准。唯一测不到的「浮层提升到 Top Layer」由保留的契约断言覆盖，且本轮不碰浮层挂载方式。

### 与后端那半的关系

同一个能力被一条测试线切成两半这件事，本轮只补齐前端这半，不合并两半。前端与服务端各扫一遍本地记录是有意的（见 Implementation Decisions），因此两侧的断言天然不重叠：后端测「怎么向 OneBot 翻页」，前端测「怎么编排一次查找并把结果交给界面」。
