# 04 — 配置规格 module 与双向键集断言

**What to build:** 配置项的默认值从此只写一次。建立配置规格——插件全部 31 个配置项的唯一权威声明，Schema 的默认值改从它读取。同时加一条双向键集断言，让「漏掉一个配置项」从静默出错变成编译失败。这是整套改动的 expand 步骤：规格与现有字面量并存，后续 ticket 再按消费方逐个迁移。

**Blocked by:** 03 — 配置模块目录化并保持引用路径。

**Status:** ready-for-agent

**参考:** `.scratch/config-spec/spec.md`；koishi 依赖禁令与配置类型不派生的理由见 ADR 0003。

- [ ] 配置规格声明全部 31 个配置项，逐项记录键名、默认值、是否为镜像配置项、空字符串是否视为未设置
- [ ] 配置规格支持「无默认值」形态；好感度 scopeId 使用该形态且不是镜像配置项
- [ ] 配置规格不引用 koishi，也不引用任何间接引用 koishi 的 module（ADR 0003）
- [ ] Schema 的默认值全部改为从配置规格读取
- [ ] Schema 的分组划分、分组顺序、字段顺序、控件类型、数值上下限、说明文案全部不变
- [ ] 对外导出的配置类型仍是手写 interface，未改为派生类型（ADR 0003）
- [ ] 存在一条双向键集断言：配置规格键集与该配置类型键集完全相等，多一个或少一个都编译失败
- [ ] 从配置规格里删掉任一项后编译失败，向配置规格里加一项而不同步配置类型也编译失败
- [ ] 完整构建后重启，逐组核对配置面板的分组、字段顺序、控件与文案，与改动前一致
- [ ] 全量测试通过
