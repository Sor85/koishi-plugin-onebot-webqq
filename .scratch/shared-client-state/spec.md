# 客户端共享状态：把 globalThis 单例这条危险知识收成一处

**Status:** ready-for-agent

**来源:** `/improve-codebase-architecture` 的候选 ⑧，经 `/grilling` 两轮定型。相关决定：ADR 0008（本轮新立，记录建立前端共享层的判据）、ADR 0001（前端模块边界，其中「不建立前端共享目录」那条的例外条件在本轮被触发）。

## Problem Statement

前端有五个模块各自持有一份跨模块实例共享的状态：入口会话态、配置镜像、小胶囊状态、观察窗运行时状态、机器人状态。五处都用同一段兜底代码把状态挂到全局对象上，**逐字相同**，只有键名、类型与工厂三处不同。

这段代码不是可有可无的样板。开发环境下 portal 与 Vite 的文件服务会把同一份源码解析成两个模块实例（入口走软链路径，子模块被改写成真实源码路径，且部分改写带版本查询串、部分不带），于是同一个文件出现两个 URL、两份模块作用域。漏写这段兜底的后果是写入方与读取方拿到不同的引用，表现为一整类症状：

- 点头像打不开观察窗。
- 配置里开了发送功能，输入区却不出现。
- 主胶囊的隐藏配置只对日志页生效。
- 头像小胶囊的未读徽标不随观察窗未读数更新。
- 群消息右键菜单里没有「贴表情」与「撤回」，因为权限判断读不到当前操作员。

前两条与第三条都真实发生过并已修复——每一次都是漏写了这段兜底。

维护者这一侧的问题是这条知识没有归属地。**症状**的注释五份各不相同（各自绑着具体状态，是有价值的事故记录），但**机制**的解释只有小胶囊那一处写全了，其余四处互相指「与某某同理」——四个文件为同一条解释交叉引用，正说明它无家可归。守卫也只有六条读源码文本的断言（断言某个键的字面量在、断言文件里出现过全局对象名），那种断言证明不了「两次 import 拿到的是同一份状态」。

## Solution

把「挂到全局对象、按键去重、首次创建」收进一个共享状态 module，调用点各剩一行：给一个键、给一个工厂，拿回那份唯一的状态。

于是这条不变量第一次有唯一的可测点——重置模块缓存后重新 import，拿到的引用必须是同一个。分散在五处时，要写这条断言得写五遍，没人会写，这正是它至今只有源码文本守着的原因。

管理员看到的行为完全不变；五个模块的导出面一行都不变，因此十几个消费方零改动。

## User Stories

### Koishi 管理员

1. 作为管理员，我想点主胶囊上的头像就能打开观察窗，这样入口是可靠的。
2. 作为管理员，我想在配置里开启发送功能后输入区真的出现，这样这个开关是可信的。
3. 作为管理员，我想主胶囊的隐藏配置在所有控制台页面生效，而不是只在日志页。
4. 作为管理员，我想头像小胶囊上的未读徽标跟着观察窗的未读数变化，这样我不用打开观察窗就知道有新消息。
5. 作为管理员，我想群消息的右键菜单里始终能看到「贴表情」与「撤回」，这样权限判断不会把我误判成没有操作员身份。
6. 作为管理员，我想上面这几条在插件热重载之后仍然成立，这样调试期间不需要刷新整个控制台。
7. 作为管理员，我想开发环境与生产环境表现一致，这样在开发环境里验过的东西部署后不会变样。
8. 作为管理员，我想这轮改动之后界面与交互一点变化都没有，这样它对我是完全透明的。

### 插件维护者

9. 作为维护者，我想新增一份跨模块实例共享的状态时只写一行，这样结构上不可能再漏写兜底。
10. 作为维护者，我想那条「同一份源码会被解析成两个模块实例」的机制解释只存在一处，这样新人读一遍就懂，不用在四个文件之间跳转。
11. 作为维护者，我想五处各自的症状注释留在原地，这样每份状态旁边仍然写着「漏了会怎样」，而不是被搬进一张与代码对不上的清单。
12. 作为维护者，我想「两次 import 拿到同一份状态」变成一条真正的运行时断言，这样这条不变量坏了会变红，而不是等到某天在开发环境里表现成怪现象。
13. 作为维护者，我想「同一个键第二次调用不会重新执行工厂」有断言，这样不会出现状态被悄悄重建、之前的写入丢掉。
14. 作为维护者，我想「不同键互不干扰」有断言，这样五份状态不会因为键去重的实现失误而串台。

16. 作为维护者，我想删掉那六条读源码文本的断言，这样测试不会用「某行字还在」冒充「不变量还成立」。
17. 作为维护者，我想键仍然是调用点里的完整字符串字面量，这样在浏览器里看到全局对象上的键之后，回到源码能直接搜到它。
18. 作为维护者，我想共享状态 module 不认识任何具体领域的状态名，这样它的深度不会塌成一个转发层。
19. 作为维护者，我想卸载时清理什么仍然由组合根决定，这样共享状态 module 只回答「如何共享」这一个问题。
20. 作为维护者，我想五个模块的导出面一行不变，这样十几个消费方零改动，审查时容易确认没有夹带行为变化。
21. 作为维护者，我想求值时机保持在模块加载时，这样这次搬迁是逐字等价的，不引入惰性初始化这种新语义。
22. 作为维护者，我想建立前端共享层这件事有 ADR 记录，这样下一个读模块边界 ADR 的人不会把它当成违规。
23. 作为维护者，我想这条断言住在独立的测试文件里，这样重置模块缓存这种整图操作不会和别的测试产生顺序耦合。

28. 作为接手的 agent，我想知道本轮没有任何允许的行为改动，这样我按逐字等价搬迁处理。

## Implementation Decisions

### 共享状态 module 的接口

一个函数：给它一个键与一个工厂，拿回该键唯一的那份状态。内部吃下三件事——挂到全局对象、按键去重、首次创建。

求值时机保持在**模块加载时立即求值**，与现在五处的写法逐字等价。不做成惰性 getter：那会把求值推到首次读取，是行为改动，而且五份状态的工厂都只是建几个响应式引用，没有昂贵初始化，惰性换不到任何东西。

命名采用 `define` 前缀。已知瑕疵是这个前缀在 Vue 生态里通常指编译宏，放在普通模块里可能让人愣一下；接受它是因为它准确表达了这个函数唯一正确的用法——在模块顶层、每个键只写一次。

### 键由调用点给出

调用点传完整的字符串字面量，module 既不发明键也不加前缀。看起来加前缀更防撞，但前缀现在已经在做这件事；把它藏进 module 只有坏处——排查时在浏览器里看到全局对象上的键，回到源码 grep 却搜不到这个字符串。让 module 维护一份键的枚举表更糟：那会让它认识五个具体领域的名字。

### 放在前端共享层

module 会被入口、小胶囊、观察窗、机器人四个领域共同依赖，因此必须落在一个不属于任何领域的位置。塞进现有领域走不通：放进机器人那一侧会让观察窗依赖它（模块边界 ADR 明令禁止的方向之一），放进入口状态模块会成环（它已经依赖小胶囊与观察窗）。

模块边界 ADR 写着「不建立前端共享目录，除非前端真的出现两个以上领域共同依赖的深 module」。本轮是**行使**这个例外而不是推翻它：四个领域共同依赖，且它确实深——内化了一条真实的危险知识，删掉会散回五处（deletion test 通过）。新立 ADR 0008 记录判据；对模块边界 ADR 的唯一改动是加一行交叉引用，指路而不改决定。

### 注释怎么分

- **机制**说明（两个模块实例是怎么产生的）搬进共享状态 module，写一份。目前只有小胶囊那处写全了，以它为底本。
- **症状**注释留在各自调用点，五份都留。它们各自绑着具体状态——「隐藏配置停在默认值，于是只有日志页能隐藏主胶囊」只有在小胶囊那个文件里才有意义；搬进 module 会变成一张跟代码对不上的清单。
- 四处「与某某同理」的交叉引用删掉，它们存在的唯一理由就是机制解释无家可归。

### 不进这个 module 的东西

卸载时的状态清理不进来。它选择性地清会话态，并且写明了哪些**不能**清——配置镜像不能清，否则热重载时会出现「配置已开却不显示输入区」；机器人状态不能清，否则消息菜单会误判为没有操作员。这些判断涉及三个领域的具体状态，是组合根的职责。把清理也收进共享状态 module，它就得认识主胶囊、观察窗开关、未读数这些名字，深度立刻塌成一个转发层。

### 五个模块的导出面不变

每个模块仍然是「从状态对象上取出字段再命名导出」这个形状，只是状态对象的来路从一段内联的立即执行表达式换成一次函数调用。因此十几个消费方零 diff，这也是本轮适合当热身的原因。

入口状态模块要注意：它同时是调用点（自己有一份会话态）又是再导出方（把小胶囊、配置镜像、观察窗运行时状态的若干导出转发出去）。后者与本轮无关，不要动。

### 没有允许的行为改动

本轮是纯等价搬迁，一处可见或不可见的行为改动都没有。这与前几个候选不同——它们各自带一到两处不可见的修正。

### 不新增领域术语

共享状态 module 解决的是纯实现问题（同一份源码被解析成两个模块实例），不是领域概念。领域词汇表按约定必须完全不含实现细节，把这个机制写进去会开一个坏先例：那份文件一旦开始收纳机制名词，就会逐渐变成架构笔记。这条坑的解释归 ADR 0008 与 module 里那段注释。

## Testing Decisions

### 什么算好测试

只测外部行为。对这个 module 来说，外部行为就是「同一个键拿到的是同一份状态」这一条不变量及其推论。断言源码文本不算测行为——现有那六条正是反例：它们能证明某个键的字面量还写在文件里、能证明文件里出现过全局对象名，但证明不了两次 import 拿到的是同一份状态，而后者才是这段代码存在的全部理由。

### 接缝

**一个**，就是共享状态 module 自己的接口。这是本轮最舒服的一点：五处调用点原本各是一个无法观测的立即执行表达式，收敛之后只剩一个可直接调用的函数。

### 要测的行为

- 重置模块缓存后重新 import，拿到的引用与之前是同一个对象。
- 同一个键第二次调用不重新执行工厂（用一个记调用次数的工厂断言）。
- 不同键互不干扰，各自拿到自己的那份。
- 键确实挂在全局对象上，名字与传入的字面量一致。

第一条是核心，其余三条各自锁住一种去重实现失误。

### 断言住在独立测试文件里

重置模块缓存是整个模块图级别的操作。放进那些在顶层正常 import 这五个模块、并依赖它们实例的测试文件里，会引入测试间的顺序耦合。独立文件配合项目现有的「每个测试文件一个独立进程」设置，能让这组断言完全不受别处影响，全局对象也不会跨文件污染。

### 要删的旧断言

六条读源码文本的断言全部删除，分布在小胶囊与观察窗那两个测试文件里，形状是「断言某个键的常量声明字面量在」加「断言文件里出现过全局对象名」。接管者是上面那四条运行时断言，其中「键确实挂在全局对象上」直接对位替换了它们想守的东西。删除而不是原地替换——原地替换会把 module 缓存重置操作带进那两个大文件。

### Prior art

同类的「直接实例化 module、注入假实现、读返回值」断言在仓库里已有先例：通知菜单那条与会话内查找那一整个测试文件。本轮更简单，连注入都不需要，因为这个 module 唯一的依赖就是全局对象本身。

## Out of Scope

- 改变任何一份共享状态的内容、类型或导出名。
- 把卸载时的状态清理逻辑搬进共享状态 module。
- 给键加前缀、改键名，或把键收进枚举表。
- 改成惰性初始化，或改变求值时机。
- 动入口状态模块那一大块再导出。
- 推翻模块边界 ADR 里关于前端领域依赖方向的任何一条。本轮只行使它自带的例外条件，并把判据记进新 ADR。
- 给领域词汇表新增词条。
- 顺手整理五个模块里与共享状态无关的部分。

## Further Notes

### 为什么一张票

改动面是五个模块各删十几行加一行调用、一个约 25 行的新 module、一个新测试文件、一条新 ADR 加一行交叉引用。一个上下文窗口装得下。

更重要的是这属于「迁一半最难看」的改动：module 建好但还有三处保留旧写法时，正好是这条不变量最容易被漏写的状态——也就是本轮要消除的那个形态。虽然算机械改动，blast radius 只有五个文件，不需要拆成展开与收缩两段，一张票就能落绿。

### 没有第六处漏写

核对过：五个模块之外，前端没有其他模块级的共享响应式状态。有一个会话状态 module 看着像候选，但它的响应式引用是在 composable 里按次创建的，顶层导出全是纯函数，不需要跨模块实例共享。所以本轮是收敛已有的五处，不是补救遗漏。

### 与前几轮的关系

这条不变量此前被触发过三次真实故障，其中一次（主胶囊隐藏配置只对日志页生效）就在最近的提交里。收敛之后，这类故障从「取决于有没有记得写那段兜底」变成「取决于有没有调用那个函数」——后者漏掉时类型检查就会报错，因为拿不到状态对象。
