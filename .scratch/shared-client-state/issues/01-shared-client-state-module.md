# 01 — 共享状态收成一个 module

**What to build:** 前端那五份跨模块实例共享的状态（入口会话态、配置镜像、小胶囊状态、观察窗运行时状态、机器人状态）从此共用一段兜底代码。现在五处各自把状态挂到全局对象上，写法逐字相同，只有键、类型、工厂三处不同；漏写这段的后果是一整类故障——点头像打不开观察窗、配置开了输入区不出现、主胶囊隐藏配置只对日志页生效、未读徽标不更新、群消息菜单里没有「贴表情」与「撤回」。前三条真实发生过并已修复，每次都是漏写导致的。

改完之后新增一份共享状态只写一行，漏写会在类型检查阶段就报错——拿不到状态对象。更关键的是「两次 import 拿到同一份状态」这条不变量第一次有唯一的可测点：分散在五处时要写五遍同样的断言，没人会写，这正是它至今只有读源码文本的守卫的原因。

**管理员看到的行为完全不变，本轮没有任何行为改动。** 五个模块的导出面一行不变，因此十几个消费方零 diff。

**Blocked by:** 无 — 可以立即开工。

**Status:** ready-for-agent

**参考:** `.scratch/shared-client-state/spec.md`；建立前端共享层的判据见本票要新立的 ADR 0008，其例外条件出自模块边界 ADR 0001。

五处调用点用 `globalThis` 一次 grep 即可全部定位——不列路径，路径会过时。

- [ ] 共享状态 module 落在前端共享层，对外只有一个函数：给一个键与一个工厂，拿回该键唯一的那份状态
- [ ] 五处调用点各剩一行调用；求值时机仍在模块加载时，不改成惰性 getter
- [ ] 键仍由调用点以完整字符串字面量给出，module 既不发明键也不加前缀，源码里仍能直接 grep 到浏览器里看到的那个键
- [ ] 机制说明（同一份源码为什么会被解析成两个模块实例）搬进 module 写一份，以小胶囊那处写全了的版本为底本
- [ ] 五处各自的**症状**注释留在原地，一条不删——它们是事故记录，各自绑着具体状态
- [ ] 四处「与某某同理」的交叉引用删掉
- [ ] 五个模块的导出面一行不变；入口状态模块那一大块再导出不动
- [ ] 卸载时的状态清理仍留在组合根，不进这个 module（它涉及三个领域的具体状态，且写明了哪些不能清）
- [ ] 存在断言覆盖 4 条行为：重置模块缓存后重新 import 拿到的引用是同一个对象；同一个键第二次调用不重新执行工厂；不同键互不干扰；键确实挂在全局对象上且名字与传入的字面量一致
- [ ] 断言住在独立测试文件里；其余测试文件的运行条件不变
- [ ] 6 条读源码文本的断言已删除（断言键的常量声明字面量在、断言文件里出现过全局对象名），删除而非原地替换——原地替换会把模块缓存重置操作带进那两个大文件
- [ ] 新立 ADR 0008 记录建立前端共享层的判据（四个领域共同依赖、deletion test 通过）；模块边界 ADR 只加一行交叉引用，不改它的决定
- [ ] 本轮没有任何行为改动，可见与不可见都没有
- [ ] 逐条失效实测：去掉键去重、改成每次调用都新建、把挂载的键写错——三处都能让对应断言变红
- [ ] 全量测试通过
- [ ] `yarn typecheck` 与 `yarn build` 通过。本票是这一系列里第一张真正改前端源码的票，构建不能跳过
