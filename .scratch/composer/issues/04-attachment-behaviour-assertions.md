# 04 — 待发附件的挂载式断言

**What to build:** 待发附件的行为从此可自动验证。目前「粘贴截图有没有被认成图片」「粘贴纯文字会不会被附件逻辑吃掉」「附件转字节对不对」只能靠人手点，而其中一条错了就是发出去的内容不对。本 ticket 把这些变成挂载式断言，并删掉对应的源码文本断言。

**Blocked by:** 02 — 输入区组件搬迁与草稿光标断言。

**Status:** ready-for-agent

**参考:** `.scratch/composer/spec.md` 的 Testing Decisions「要测的行为」一节。

- [ ] 挂载式断言覆盖：按 MIME 与扩展名判定图片、视频、文件三类
- [ ] 粘贴带文件时阻止默认行为并收下文件
- [ ] 粘贴纯文字时正常插入文字，不被附件逻辑吃掉
- [ ] 可以移除单个待发附件，且释放其预览资源
- [ ] 请求放大预览时只发出对外事件，输入区不自行打开浮层
- [ ] 待发附件转成发送元素时字节正确
- [ ] 草稿为空且无待发附件时不可发送；只有待发附件时可发送
- [ ] 对应的源码文本断言已删除，删掉的每一条都能指出接管它的行为断言
- [ ] 逐条实测：故意改坏任一条附件行为时，对应断言失败
- [ ] 全量测试通过
