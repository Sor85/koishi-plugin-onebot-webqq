# 05 — 发送区占位的打桩断言

**What to build:** 发送区占位从此可自动验证。管理员看到的表现是回复条或待发附件出现时，消息列表底部让出正确的空间、气泡不被压住；这个数字算错就会压住最后一条消息。本 ticket 用打桩把它变成断言，并删掉锁占位计算式的源码断言。

**Blocked by:** 02 — 输入区组件搬迁与草稿光标断言。

**Status:** ready-for-agent

**参考:** `.scratch/composer/spec.md` 的「探针实测得到的两条限制」一节。

已实测的限制：无头 DOM 没有布局引擎，尺寸观测回调**永不触发**，取矩形恒返回 0，但可以直接覆写打桩。因此本 ticket 的断言只能是「给定上下文层高度，占位数字应为多少」，不能是「改了样式后数字自己变了」。

- [ ] 打桩给定上下文层高度后，断言输入区对外输出的占位数字
- [ ] 回复条出现与消失时，占位数字随之变化
- [ ] 待发附件出现与消失时，占位数字随之变化
- [ ] 多选模式下占位取固定值这条断言落在父层（门禁在父层，输入区不认识多选模式）
- [ ] 断言不依赖真实布局，也不依赖尺寸观测回调被触发
- [ ] 锁占位计算式的源码文本断言已删除
- [ ] 实测：故意改错占位公式时断言失败
- [ ] 全量测试通过
