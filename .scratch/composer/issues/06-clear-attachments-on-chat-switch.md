# 06 — 切换会话清空待发附件

**What to build:** 修掉一处误发风险。现状是切换会话会清掉草稿、提及菜单和回复目标，但**不清待发附件**——附件只在发送成功和组件卸载时才清。于是在一个会话里选好图片、切到另一个会话，图片还挂在输入区里，直接回车就发错人。改完之后附件随草稿一起清空。

这是本轮唯一一处用户可见的行为变化，变化方向是消除误发。

**Blocked by:** 04 — 待发附件的挂载式断言（它的验收要用到附件的挂载与选文件脚手架）。

**Status:** resolved

**参考:** `.scratch/composer/spec.md` 的 Implementation Decisions「行为修正」一节。

- [x] 切换会话时草稿、提及菜单、回复目标与待发附件全部清空
- [x] 存在挂载式断言：选入待发附件后切换会话，附件列表为空
- [x] 切换会话时释放被清掉的附件的预览资源
- [x] 发送成功后仍清空附件、组件卸载时仍释放预览资源，既有行为不回退
- [ ] 完整构建后重启，在真实浏览器里实测：在一个会话选图后切到另一个会话，预览确实消失
- [x] 实测：把切会话清附件这段去掉时断言失败
- [ ] 浏览器验证结束后关闭本次打开的标签页与自动化进程，清理工具生成的临时目录
- [x] 全量测试通过

## Comments

- 实现是输入区 `chat-key` prop 的 watch：草稿、提及菜单与待发附件一起清空，清附件走 `clearSendFiles()`，所以预览资源同时被 revoke。父层的 `watch(currentChat)` 里删掉了原来的草稿与提及菜单清理，只留下回复目标等会话层状态。
- 断言在 `tests/webqq-composer-attachments.test.ts`：选入附件后换 `chat-key`，缩略图与上下文层都消失、`revokeObjectURL` 收到该附件的 `src`、发送按钮回到禁用态；另一条确认回复条仍由会话层决定显示，切会话不会被输入区顺手清掉。草稿与提及菜单的清空断言在 `tests/webqq-composer-editor.test.ts`。
- 既有行为没回退：发送成功后清空附件、组件卸载释放预览资源，两条都有独立断言。
- 失效实测：把 `chat-key` watch 里的 `clearSendFiles()` 去掉，断言立刻变红；改回后恢复。
- 未完成：真实浏览器实测。本机 `koishi-dev` 会连真实 OneBot 与数据库，按项目既有约定不擅自启动，清单留给用户执行。
