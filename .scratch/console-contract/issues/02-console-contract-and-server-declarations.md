# 02 — 控制台契约表与服务端两处声明

**What to build:** **控制台契约**存在，服务端两处事件名声明从它派生，而且「契约声明了但没人注册」不再静默。

现在 24 个事件名在四处各写一遍，其中服务端那两处——插件上下文 module 的请求映射与包入口的全局类型声明——20 条请求逐字重复，而**包入口那份在本仓库内没有任何消费者**：注册侧的类型锚是前者，客户端的发送函数是纯字符串。所以这两份漂移时零报错。

本票之后，服务端两端各只剩一行派生，漏改哪一端都编译失败；契约里多写一条没人注册的名字会被运行期守卫抓到。

**Blocked by:** 01 — 契约要引用的载荷类型归位（契约不能引用住在沾 koishi 的 module 里的类型）。

**Status:** resolved

**参考:** `.scratch/console-contract/spec.md` 的「契约表的形态与位置」、「名字数组为什么必须存在」、「两端如何接线」、「唯一那个例外的注册点不搬」；koishi-free 明线与「不给捷径」的做法见 ADR 0003；不新开控制台目录的理由见 ADR 0001；本轮新立的那条 ADR 记着位置与边界。

- [x] 契约落在共享层的中立位置，与控制台监听器门面并列；不进任何单一领域内部，也不重开被 ADR 0001 解散过的那个目录
- [x] 请求与广播各一个 interface，另导出两者的交集；方向靠这两个 interface 表达，不靠签名形状推断
- [x] 契约 module 的 import 闭包里没有 koishi 边，也不引用插件上下文 module（那个文件 type-import 了 koishi 与控制台包）
- [x] 另导出一份只读的事件名数组，并用编译期键集断言钉住「数组元素集等于契约键集」
- [x] 插件上下文 module 的请求映射改成等于契约的请求组
- [x] 包入口的全局类型声明改成继承契约的交集
- [x] 运行期守卫：契约声明的 20 条请求全部被注册。注册端**同时**读常规注册 module 与 WebQQ 装配 module——唯一那个注册点不在常规位置的请求不搬，守卫漏掉它就等于没守
- [x] 守卫从实际注册调用读键集，**不从契约的名字数组反推**；两边都从权威派生会让断言变成同义反复（配置镜像那份四端守卫的注释里写着这条教训）
- [x] 逐条失效实测：契约加一条没人注册的名字 → 运行期守卫红；名字数组漏一条 → 编译失败；服务端任一端的派生改成手写副本并改一个字 → 编译失败
- [x] 注册**不**收成表驱动循环（理由见 spec：会把名字表与实现焊在一起，而名字表要被客户端 import）
- [x] 契约不返回、不导出任何供测试观察用的额外东西
- [x] 本轮没有任何行为改动，可见与不可见都没有
- [x] `yarn typecheck`、`yarn test` 与 `yarn build` 通过
