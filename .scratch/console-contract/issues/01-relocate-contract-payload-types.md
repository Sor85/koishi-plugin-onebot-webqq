# 01 — 契约要引用的载荷类型归位

**What to build:** **控制台契约**能引用到全部 24 条事件的载荷类型，而不会把 koishi 拖进浏览器产物。这是后面三张票的前置：契约表要被客户端 import，所以它引用的每一个类型都必须住在零 koishi 依赖的 module 里，而现在有 4 条请求的载荷类型住在两个引用了配置入口与数据库机件的 module 里。

顺带修掉一处对现实撒谎的类型：小胶囊快照里机器人列表的元素类型允许没有名字，客户端那份要求必须有，而唯一的生产者一定带名字——客户端那份才是对的。反方向客户端漏抄了一个会话字段。

管理员看不到任何变化。本票纯类型移动加一处收紧，零行为改动。

**Blocked by:** 无 — 可以立即开工。

**Status:** resolved

**参考:** `.scratch/console-contract/spec.md` 的「载荷类型搬家」与「小胶囊广播载荷那处不健全的收窄」；跨端共享 module 不得沾 koishi 这条明线见 ADR 0003；小胶囊依赖 OneBot 是认可的边，见 ADR 0001 的依赖图。
