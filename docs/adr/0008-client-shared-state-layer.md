# ADR 0008：建立 `client/shared/` 承载跨模块实例共享的状态

## 状态

已接受。

## 背景

前端有五处状态需要跨模块实例共享：入口会话态、**配置镜像**、小胶囊状态、观察窗运行时状态、机器人状态。

需要共享是因为开发环境下 portal 与 Vite 的文件服务会把同一份源码解析成多个模块实例——dev 入口走 `node_modules` 软链路径，子模块被 Vite 改写成真实源码路径，且部分改写带 `?v=<browserHash>`、部分不带，同一个文件因此出现两个 URL、两份模块作用域。写入方与读取方落在不同实例上时，状态就是两份。已经发生过三次真实故障都由此而来：点头像打不开观察窗、配置开了**输入区**不显示、**主胶囊**的隐藏配置只对日志页生效。

兜底做法是把状态挂到 `globalThis` 上并按键去重。这段代码在五处逐字重复，连解释机制的注释也重复——而且只有小胶囊那处写全了，其余四处互相指「与某某同理」，四个文件为同一条解释交叉引用。

ADR 0001 的前端模块边界里写着：不建立 `client/shared/`，除非前端真的出现两个以上领域共同依赖的深 module。

## 决策

建立 `client/shared/`，把「挂到 `globalThis`、按键去重、首次创建」收成一个 module。

**这是行使 ADR 0001 那条例外，不是推翻它。** 判据逐条对齐：

- **两个以上领域共同依赖**：入口、小胶囊、观察窗、机器人四个领域都要用它。
- **深**：接口是一个函数（一个键、一个工厂），实现内化了上面那整条 Vite 双实例知识。deletion test 通过——删掉它，这段代码连同它的解释会散回五处。

module 不认识任何具体领域的状态名。键由调用点以完整字符串字面量给出；卸载时清理什么仍由组合根决定。这两条是它保持深度、不塌成转发层的边界。

其他放置方案都会违反 ADR 0001 已有的依赖方向：放进机器人那一侧会让观察窗依赖它；放进入口状态模块会成环，因为它已经依赖小胶囊与观察窗。

## 考虑过的替代方案

- **维持五份复制**：漏写一处不会报错，只会在某天表现成开发环境下的怪现象，而这已经发生过三次。
- **放在 `client/` 根目录的单文件、不建目录**：回避的是目录名而不是依赖关系，实质相同，但让人看不出这是有意的共享层，下一个人更可能再复制一份。
- **让 module 维护一份键的枚举表**：它就得认识五个领域的名字，深度塌成转发层；而且浏览器里看到的键在源码里搜不到。
- **改成惰性求值**：把求值时机从模块加载推到首次读取，是行为改动，而这五份状态的工厂只是建几个响应式引用，惰性换不到任何东西。

## 后果

- 新增一份跨模块实例共享的状态只写一行。漏掉时类型检查会报错，因为拿不到状态对象——故障模式从「取决于有没有记得写那段兜底」变成「取决于有没有调用那个函数」。
- 那条不变量有了唯一的可测点：可以断言重置模块缓存后重新 import 拿到的是同一个引用。分散在五处时这条断言要写五遍，因此从来没有写过，只有读源码文本的守卫。
- 前端从此有一个共享层，它的准入门槛就是本 ADR 的判据——两个以上领域共同依赖，且删掉会让复杂度散开。不满足的东西不要往这里放：这个目录一旦变成杂物间，ADR 0001 那条禁令当初要防的事情就回来了。
- 症状注释仍然分散在五处调用点，这是有意的。它们是事故记录，各自绑着具体状态，集中之后会变成一张与代码对不上的清单。
