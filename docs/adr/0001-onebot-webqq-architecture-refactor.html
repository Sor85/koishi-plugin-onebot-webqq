目标代码架构

目标不是多建目录，而是把 seam 放到调用者真正需要改变行为的位置：OneBot adapter seam、Console transport seam、storage seam。ChatLuna 相关代码按 capsule 和 webqq 的真实消费方归属。

不建立顶层 chatluna/ 或 integrations/chatluna/。当前 affinity 只服务 WebQQ；完整 think 内容也只由 WebQQ 展示，胶囊只记录活动状态和 duration。

shared 只保留 record.ts。OneBot field readers 和 action/id/time/result helpers 归 onebot/data.ts；readStructuredText 归 WebQQ thinking；affinity number reader 内联到 webqq/affinity.ts。

onebot 不长期导出 WebQQ* view model 类型；这些类型归 webqq/types.ts。胶囊消息输入也不能复用 WebQQ session helper，避免 capsule -> webqq 依赖。

Deepening candidates

每个候选都按 module、interface、implementation、depth、seam、adapter、leverage、locality 来描述。它们不是一次性全做，按后面的 top recommendation 排序。

Deepen the plugin runtime module

Strong in-process
Files
  • src/index.ts
  • src/runtime/*
  • src/capsule/register.ts
  • src/webqq/register.ts
  • src/capsule/chatluna-activity.ts
Before
src/index.ts
wide interface, mixed implementation
capsule
webqq
chatluna
console
After
src/index.ts
small interface: apply(ctx, config)
src/runtime
capsule register
webqq register
capsule ChatLuna activity
implementation absorbs dependency wiring

Problem：src/index.ts is shallow; deleting it would spread its ordering constraints across every feature.

Solution：Make a deep runtime module with one small interface and internal seams for capsule and WebQQ registration.

  • locality: wiring bugs concentrate
  • leverage: one runtime interface
  • tests hit one seam

Problem：src/onebot/types.ts leaks WebQQ models across the OneBot seam; card/media/text normalization, group sender metadata fetching, and raw reaction interception are also WebQQ adapter behavior.

Solution：Move WebQQ* types to webqq/types.ts; keep OneBot as a deep protocol module and make WebQQ conversion an adapter module.

  • locality: protocol changes isolate
  • leverage: adapter owns conversion
  • interface stops leaking models

  • leverage: stores import less
  • interface mirrors domains

Problem：Storage codecs and adapter choices are split across server and client modules.

Solution：Put schema, codec, scope, state cache, message cache, and recall cache behind one storage interface per side.

  • locality: persistence bugs concentrate
  • leverage: one codec per model
  • adapter seam becomes real
Top recommendation

Start with pure structure migration, then deepen runtime and the OneBot adapter seam.

First move files by domain without changing behavior, so import paths and ownership become visible. Then split src/index.ts into runtime/register modules and move WebQQ conversion behind src/webqq/adapters/onebot.
