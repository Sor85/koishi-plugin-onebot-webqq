# ADR 0010：控制台契约表的位置与边界

## 状态

已接受。

## 背景

控制台与插件之间有 24 个事件名：20 个请求和 4 个广播。此前每个名字要写 3 到 4 遍——服务端的请求映射、包入口的全局类型声明、实际注册处、客户端的调用处——而没有任何一处能保证这几遍写的是同一个字符串。包入口那份声明在本仓库内甚至没有任何消费者：注册侧的类型锚是前者，客户端的调用是纯字符串，两份漂移时零报错。

失效形态全是静默的。请求名写错，前端拿到 `undefined`，界面显示「加载聊天历史失败」而日志里查不到原因。广播名写错更糟：没有报错也没有失败提示，只是实时消息不再出现、小胶囊计数停在旧值，看起来像机器人掉线了。

**控制台契约**把这 24 个名字连同各自的载荷与返回形状收成唯一权威声明。它要同时被服务端与客户端引用，因此落进 ADR 0003 划定的那条明线之内——那是这条明线的第二次行使，第一次是配置规格。

## 决策

**契约表落在共享层的中立位置**，与控制台监听器门面并列。不放进任何单一领域内部：契约同时管小胶囊的两个广播名，放进 WebQQ 会让那个领域拥有小胶囊的事件，撞上 ADR 0001 的依赖方向。也不重开控制台目录——ADR 0001 明确解散过它。也不留在插件上下文 module：那个文件 type-import 了 koishi 与控制台包，客户端引用它就越过明线。

**契约表及其闭包不得引用 `koishi`，也不得引用任何间接引用 `koishi` 的 module。** 与配置规格同一条规矩，同一个理由：违反它会把整个 koishi 静默打进浏览器产物，不产生任何报错。本 ADR 同时要求为这条规矩立一条守卫——读源码做 import 闭包，而不是读构建产物。

**契约本体是类型层的两个 interface**（请求一个、广播一个，另导出交集），不是运行时值表。它不需要提供默认值，做成值表就得给每条写占位值。**但必须额外导出一份只读的事件名数组**，并用编译期键集断言钉住它等于契约的键集：类型层的 interface 在运行时不可枚举，而运行期恰好守着唯一无法编译期检查的失效形态——契约声明了但没人注册。

**客户端类型垫片的重载不留字符串兜底分支。** 留了就等于没约束。真出现要发送非契约事件的需求时再加，判据是「有真实的非契约消费者」，不是「撞上编译错误」。

**客户端那三个类型文件保留成从服务端 re-export 的门面，不删除。** 几十个消费方的 import 路径不动，客户端专属的东西也还有地方住。

## 考虑过的替代方案

- **只加一条守卫断言，不动来源**：最省，但守卫只能在名单已经写错之后报警，写错的机会仍然是四处。而且只锁名字锁不住载荷字段漂移与返回类型撒谎，那两者占失效形态的大半。
- **只收名字，载荷类型两端各自维护**：客户端仍然要手转返回值，两份手抄的类型文件继续漂。核对时它们已经漂了一处。
- **契约表紧邻请求注册代码**：位置最直觉，但会让 WebQQ 领域拥有小胶囊的广播名。
- **契约表留在插件上下文 module**：改动最小，但那个文件碰了 koishi，客户端引用它就越线。
- **做成运行时值表**：与配置规格形状一致，但契约没有值可提供，每条得写占位值——把类型信息塞进值层。
- **让守卫测试自己维护一份 24 条清单**：省掉名字数组，但那份清单漏一条时编译期抓不到。它不是契约的一端，而是第五份副本，正是本轮要消灭的东西。
- **注册收成表驱动循环**：能砍掉一半注册代码，但会把名字表与 handler 实现焊在一起，而名字表要被客户端引用——一沾实现就把整条依赖链拖进浏览器产物，且不报错。
- **重载留一条字符串兜底分支**：让「万一要发非契约事件」有路可走，但同时让约束形同虚设。
- **删掉客户端类型文件、把 import 重指到服务端**：结构更干净，但要改几十个消费方，而门面式 re-export 已经拿到全部收益。
- **读构建产物的守卫**：最贴近真实后果，但要求先跑构建；`yarn test` 单跑时产物可能是旧的或不存在，做成「产物不存在就跳过」等于在最需要它的时候静默失效。

## 后果

- 四端里任何一端漏改事件名或载荷形状都编译失败，而不是等到运行时表现成「加载失败」或者干脆什么都不发生。
- 载荷类型全仓只有一份，两端不再各自漂移。
- 契约声明了但没人注册会被运行期守卫抓到；反方向（注册了但契约里没有）编译期就红。
- 撞上「某个事件名编译不过」时，正确反应是回头看哪一端的声明不对，**不是**给重载加兜底分支。要加兜底需要先推翻本 ADR。
- 共享层从此有两个跨端 module（配置规格、控制台契约）。给任一个加一条 koishi 边会让 import 图守卫变红；那条守卫是 ADR 0003 那条规矩第一次有的机械保障。
- 契约本体运行时零成本，名字数组是唯一落到产物里的东西，且客户端不引用它。如果它某天出现在浏览器产物里，说明有人把它当运行时数据用了——那时要判断是否已经有了非守卫的消费者。
