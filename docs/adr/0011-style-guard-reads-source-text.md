# ADR 0011：样式守卫查源码文本，不查编译产物也不查浏览器 computed 值

## 状态

已接受。

## 背景

样式守卫（`tests/style.test.ts` 与 `tests/webqq-typography.test.ts`）读 SCSS 源码回答「这条规则里写了这条声明吗」，共 700 余条断言。它守的东西全是管理员看得见的：浮层叠放次序、撤回消息的删除线、气泡圆角、头像尺寸、主胶囊毛玻璃、鼠标指针不被覆盖。

Sass 编译器已经在开发依赖里（`sass`，客户端构建要用），Playwright 也能在真实浏览器里读 computed 值（真机验证一直这么做）。所以「为什么这层守卫还在读源码文本」一定会被反复提出，架构复查已经提过一次。

## 决策

样式守卫的主体是**样式源码文本**，经由共享的样式查询 module（`tests/helpers/style-query.ts`）切片。不引入 Sass 求值，也不把这层断言搬到浏览器。

理由是这些断言的判据本身就是源码级的。项目自己的样式规则也是这么表述的：

- 「任何情况下都不得通过 CSS、HTML 属性或脚本设置鼠标指针样式；不得新增任何 `cursor` 声明」——判据是「源码里没有这条声明」。
- 「字号必须来自一套集中定义的标度令牌，不得在各处硬编码字面值」——判据是「源码里写的是 `var(--onebot-webqq-font-md)` 而不是 `13px`」。
- ADR 0002「工作区层不得声明 `backdrop-filter`」——判据是「那条规则的本级没有这条声明」。

Sass 求值会把这些判据要守的东西改写掉：令牌被代入、嵌套被展开、`&` 消失。「编译更准」这个直觉在这里是错的——全部断言里只有一条依赖 SCSS 的嵌套语法存活（群信息按钮的 `&.is-active`），编译能多解析的东西几乎没有，而编译会让一整类源码级规则失去检查对象。

浏览器读 computed 值是**另一层**验证，不是这一层的替代品。它跑不了 700 条断言，也看不到「源码里写没写」——`cursor: default` 与「没有声明 cursor」的 computed 值相同，而项目规则禁的是后者。排版治理的验收要求实测 computed 字号分布，那条要求不受本 ADR 影响，两层各守各的。

代价是显式的：文本切片器只有正确访问器才能守住它想守的东西。历史上正是这里出过三处静默失效——切不出内容时返回空串让负向断言变成永真；不校验逗号前导让写成选择器列表首项的规则永远查不到；惰性正则在目标规则缺声明时读到后面某条无关规则的值。

所以本决定附带一条硬约束：**全部样式查询必须走 `tests/helpers/style-query.ts`，不得在测试文件里另写切片器。** 那份 module 的语义是这条决策能成立的前提：

- 找不到目标就报错，不返回空串。
- 同一个选择器有多处定义时报错，要求调用点收窄来源；不提供「取第几处」这样的序号参数，否则断言会依赖规则在文件里的排列顺序。
- 默认取规则的**本级声明**，一条声明不因为写在子规则里就算通过；需要嵌套内容时显式改用块访问器。
- 剥注释是内置行为，不靠调用点各自记得做——注释里带花括号和选择器字面量是常态。
- 默认来源覆盖**全部**样式文件，并由一条守卫比对那份清单与磁盘实况。漏掉一个文件，针对它的规则查询会静默查不到，那个文件就只剩「整份源码里出现过这串字」这种最弱的守卫。

## 考虑过的替代方案

- **用已有的 Sass 编译器做真解析**：见决策。另外它还要求断言改写参数（令牌变成字面值），而参数正是这层守卫的可读性所在。
- **改成浏览器读 computed 值**：另一层验证，见决策。
- **两套并存，源码断言只留禁令类**：等于把「谁归哪层」变成每次新增断言时的判断题，而这两层的失败形态完全不同，混着写会让人以为源码断言能替代真机验证。

## 后果

- 下一轮架构复查再提「换成真解析」时，判据已经写下来了：先证明有一整类判据不能用源码文本表述，再推翻本 ADR。
- 新增样式断言时不需要选层：源码级判据进样式守卫，视觉与几何结果进真机验证。
- 样式查询 module 的**查询接口**要保持窄。它现在有五个查询方法（本级声明、规则是否存在、块的全部内容、两个字面量之间、某条声明的值）；再加查询方法需要说明为什么现有五个表达不了。排版守卫特有的「取第 N 条规则的选择器清单」就是刻意留在原文件而没有进 module 的例子。
- 唯一性检查让每次查询都要扫一遍来源里的全部花括号，样式守卫从 14ms 涨到约 190ms。这是买安全网的代价，不做进一步优化。
